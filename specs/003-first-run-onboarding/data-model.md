# Data Model: First-Run Virtualization Onboarding

## OnboardingAssessment

Connection-scoped, read-only readiness result returned when the application starts, the active
connection changes, or the user opens the VM creation flow.

| Field | Type | Rules |
|---|---|---|
| `checkedAt` | RFC 3339 timestamp | Generated by the backend for every assessment. |
| `connection` | safe operation connection identity | Must be the connection captured for this request; never a fabricated local URI. |
| `scope` | `local_system`, `local_session`, `remote`, `test` | Determines whether local setup guidance can be offered. |
| `distribution` | `DistributionProfile` or scoped unknown profile | Local system uses Feature 001 detection; remote/test/session results do not claim local package guidance. |
| `overallState` | `ready`, `degraded`, `unavailable` | Derived from required connection capabilities and usable storage. |
| `capabilities` | `CapabilityResult[]` | Includes connection access, emulator/KVM where applicable, firmware, TPM, network availability, and storage summary. |
| `storage` | `StorageReadiness` | Contains safe pool choices and next action. |

## StorageReadiness

Read-only description of the current connection's candidates for a requested new disk.

| Field | Type | Rules |
|---|---|---|
| `connectionId` | string | Must equal the assessment and captured operation connection. |
| `requiredBytes` | optional unsigned integer | Derived from requested disk size for preflight; absent for generic first-run assessment. |
| `pools` | `StorageChoice[]` | Discovered through libvirt; no synthesized `default` item. |
| `state` | `ready`, `selection_required`, `unavailable`, `insufficient_capacity` | `ready` requires an explicit eligible selection for a VM preflight. |
| `recoveryAction` | safe action descriptor | May direct inspect/create/activate/reselect; host mutation requires confirmation. |

`StorageChoice` uses the existing libvirt pool UUID as `id` and contains `name`, `state`,
`poolType`, `capacityBytes`, `allocationBytes`, `availableBytes`, and `autostart`. A
filesystem path must not be shown in routine onboarding output.

Eligibility for a new disk is: pool belongs to the captured connection, is active, can be queried,
and has `availableBytes >= requiredBytes`. Inactive or undersized pools remain explainable choices
but cannot be submitted as selected storage.

## GuestCapabilityReview

Comparison between the requested `VmConfig` and the captured connection before resource creation.

| Field | Type | Rules |
|---|---|---|
| `requirements` | normalized guest requirements | Derived from firmware mode, TPM request, disk creation mode, and selected network. |
| `capabilities` | `CapabilityResult[]` | Each unavailable capability names the user impact and safe recovery guidance. |
| `storage` | `StorageReadiness` | New-disk modes require a selected eligible pool; import mode does not create a volume. |
| `canCreate` | boolean | True only when all required conditions are available and selection ownership matches. |
| `connectionId` | string | Must match the selected operation connection at review and creation time. |

## VM Creation Request change

Add optional `storagePoolId` to `VmConfig` at the TypeScript/Rust IPC boundary. It becomes
required for `iso`, `network`, and `manual` installation types, and is ignored for `import`
where the existing disk is used as-is. The backend validates it by UUID immediately before volume
creation; it never falls back to a named pool.

## GuidedSetupAction

An explicit transition from an unavailable storage assessment into the existing storage-pool
creation or activation UI.

```text
inspect -> user chooses setup -> show connection + target + effects -> confirm -> libvirt mutation
        -> refresh connection-scoped assessment -> choose eligible pool -> VM preflight
```

Cancelling at any point returns to inspection with no host mutation. Failed mutation returns an
outcome and recovery action, then refreshes the observed state rather than assuming success.

## ReadinessRepairAction

Backend-derived descriptor attached to an unavailable capability. It contains a closed `id`, mode
(`automated`, `manual`, or `navigate`), safe title/effect text, privilege and confirmation flags,
expected connection ID, and manual steps. It contains no UI-provided executable input.

## ReadinessRepairResult

Terminal result containing action ID, connection ID, a safe summary, and an `applied`, `rejected`,
`cancelled`, `failed`, or `inspection_required` outcome. Raw process output never crosses IPC.
